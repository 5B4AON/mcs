8.1  Sound Card Channel Routing

Each stereo sound card has two channels: Left and Right. Morse Code Studio routes each output (sidetone, opto, pilot) to a specific channel on a specific device. This lets you use a single sound card for multiple purposes.

The rule: Two outputs must not share the same channel on the same device. If there is a conflict, the application shows a warning.

Single sound card — choose 2 of 3: A stereo card has only two channels but there are three possible outputs (sidetone, opto, pilot). You can enable any two. To use all three, add a second USB sound card.

8.2  Device Profiles

When you save settings, they are stored against the current set of audio devices connected to your computer. This is called a device profile.

Settings changes take effect immediately. Saving keeps them for future sessions on that device profile. While there are unsaved changes, the Save button at the bottom of Settings is active; when everything is saved it reads "Saved ✓". Next to it, Revert (after you confirm) discards the unsaved changes and goes back to the settings last saved for this device profile. Revert is greyed out when there is nothing to go back to. Settings also reports if a profile or browser storage is unavailable.

If you later connect a different set of devices (e.g. plugging in a USB sound card at home vs. a portable station), the application detects the change and loads the matching profile automatically. Each hardware configuration is remembered separately.

If no profile matches the current devices, the application creates a new profile with default settings and shows a yellow banner asking you to review and save.

Presets: Save, Export, and Import

Device profiles follow your audio devices automatically. If you also want setups you name yourself, such as "Home station" or "Classroom", open Presets from the kebab menu (main screen or full screen), the header of Settings or the header of the Setup Wizard. You can save the current setup as a preset (names are up to 40 characters and not case sensitive), update a preset with your current settings (after confirmation), rename, duplicate, delete, and export a preset to a local JSON file. Export first shows the file name so you can change it, and nothing downloads until you press Save. Presets are kept in this browser separately from device profiles.

To move a setup to another browser, export the preset there and use Import here, then press Load after naming it. Import only adds the file to your preset list; it never changes your running settings. To use a preset, choose Review and apply. You see a grouped before-and-after list first, showing only the parts that changed (larger structured settings are collapsed under Before: and After:), and nothing changes until you press Apply (or Back to return to the list). Applied settings become active immediately but are not saved to the current device profile; use Save in Settings separately to keep them.

RTDB channel secrets are never saved in presets or files. Applying a preset keeps the secrets already stored in this browser and will not enable an RTDB direction if its secret is empty. Audio and MIDI device identifiers and serial port numbers are not portable identities. If a target cannot be verified in this browser, its setting is left unchanged. Each keying or relay destination that would be newly enabled or redirected must be acknowledged separately before you can apply.

Example — Home vs. portable

At home: desktop PC with a built-in sound card plus a USB card for keying. Portable: laptop with only its built-in audio. Each setup has different device IDs, so Morse Code Studio saves and loads the correct settings automatically.

8.3  Fullscreen Mode

The main toolbar has a ⛶ button that opens the Full-screen conversation directly.

Independent Display Buffers

The application maintains two independent FIFO text buffers:

  • Main Output — the combined decoder/encoder output panel on the main screen.
  • Full-screen conversation — the shared RX/TX conversation log.

Each buffer receives text from the same data sources (decoded characters, sent encoder characters, and Firebase RTDB input) but can be cleared independently. Pressing the Clear button (🗑) opens a context menu with Output area (clears the current buffer only) and All text areas (clears both buffers at once). The menu also has an Input area option that empties the text-entry field (in full screen, the text typed in Type mode) without affecting any log; it also stops a replay in progress.

Buffers are capped at approximately 5 000 characters (~2× a full screen of text). When the limit is reached, the oldest characters are silently discarded (FIFO). The full-screen conversation persists across close/reopen — you will not lose its history by switching Key/Type.

Full-screen conversation

Large, scrollable RX/TX text with inline pending encoder text. The toolbar includes a Key/Type toggle beside Close: Key uses mapped physical keyboard keys and keying surfaces; Type captures text while displaying it inline. The toolbar shows read-only WPM indicator pills (RX, TX, Keyer) and a CW level meter (when CW input is enabled). The kebab menu (⋮) contains a collapsible Morse Speeds block (RX and TX with reset buttons, Encoder and Keyer with −/+ buttons), a collapsible Styling block (only one of the two is open at a time), the Lens switch, and links to the Symbols Reference and Help. When Firebase RTDB input or output is active, a small RTDB status indicator (wifi icon) turns green in the toolbar.

Responsive Toolbars

On narrow screens, the main controls bar and each fullscreen modal toolbar automatically collapse overflow controls into a kebab menu (⋮). Essential buttons — Start Audio on the main screen, and Close / Clear in fullscreen modals — remain visible at all times. Tap the ⋮ button to access the remaining controls in a dropdown. A Symbols Ref and Help entry at the bottom of each kebab menu provide quick access to the symbols reference panel and the built-in help system. The toolbar restores to its full inline layout when the window is wide enough.

Display Customisation

The following display settings are available in the full-screen conversation and are saved with your settings (per audio device configuration, like the rest):

  • Font size — A multiplier from ×1.0 to ×10.0, changed with the round − and + buttons (hold one down to change it quickly). The text size first fits the screen on its own (it shrinks on a small phone and grows on a very large monitor); this multiplies that size, so ×1 is the fitted size and ×2 is twice as large.
  • Font — Typewriter (the default), Classic, Readable or Cockpit. The fonts are built into the app, so they look the same on every device and keep working offline.
  • Row spacing — Vertical spacing between conversation lines, from ×1 (tightest) to ×10 (widest) in whole steps. Lines never touch or overlap, and with very large text the spacing tightens (and, if needed, the text is limited) so that at least three lines stay visible above the touch keys.
  • Colours — Custom colours for RX text, TX text, buffered text, currently-sending character, and background.

The Key / Type choice, Lens and all the display settings above (font, size, row spacing and colours) are remembered with your settings and are included in Presets and settings files. Defaults: Key, Lens off, Typewriter, 24 px.

8.4  Text Blurring

Found in Settings → Other. When this is on, text is blurred on the main screen and in the full-screen views. It turns the app into a copy trainer: you listen, write down what you heard, then reveal the text to check.

The Applies to selector controls which text streams are blurred:

  • RX Only — only received (decoded) text is blurred.
  • TX Only — only transmitted (encoded) text is blurred.
  • Both — all text is blurred.

To reveal the hidden text, press and hold the eye button (👁️) that appears when blurring is active. The text fades in with a 250 ms animation while you hold the button and blurs again when you release it. In the fullscreen conversation views, user-name tags from RTDB relay messages remain visible even when the text is blurred, so you always know who is transmitting.

Replay button

While text is blurred, a replay button (a circular arrow with a play triangle) sits directly above the eye button, on the main screen and in full screen. Use it to listen again without revealing the text.

  • What is replayed — the last line on screen (the most recent run of RX or TX text). In Copy Practice it is the sequence that just finished.
  • Silent on screen — the replay is not added to the text again and Lens does not change, so the blurred text stays exactly as it was.
  • Same outputs as typed text — the replay is sent at the Encoder speed (with Farnsworth timing if enabled) through every output you use: sidetone, opto/key output, serial, MIDI, WinKeyer, RTDB and vibration. When it would key or relay externally, the usual Confirm external send dialog appears first (in Copy Practice the practice pipeline setting decides, as for normal practice).
  • Pause and resume — use the send button. In Type mode of full screen it is the transmit button; in Copy Practice it is the practice Pause / Resume button. A character that was cut short plays again in full when you resume.
  • Stop — while a replay plays or is paused the replay button turns into a stop square; press it to end the replay. Clear → Input area stops it too.
  • When it is unavailable — the replay and eye buttons are disabled while there is no text on screen. Replay is also disabled while something else is being sent, while the input area holds unsent text, and in Copy Practice until the sequence has finished.

8.5  Farnsworth / Wordsworth Timing

Found in Settings → Other. Farnsworth timing is a way to learn Morse. Each letter is sent at full speed (your Encoder WPM), but the pauses between letters and words are longer, so the overall (effective) speed is lower. You learn the sound of letters at real speed and still have time to think.

Did you know?
Who was Farnsworth?

Farnsworth timing is named after Donald R. “Russ” Farnsworth (W6TTB), a radio amateur. The idea is to send each letter at full speed, so you learn its sound as a whole, and to stretch only the pauses to give your brain time to catch up.

Wordsworth mode makes only the pauses between words longer. Letters and the gaps between letters stay at full speed. It suits people who know every letter on sight but need a moment to recognise each word.

Controls

  • Applies to — Both (the default), RX Only or TX Only. TX covers the encoder and keyed outputs (sidetone, serial, MIDI, vibration). RX covers playback of received letters (for example from Firebase RTDB).
  • Mode: Effective WPM — the overall speed you want, from 5 up to your Encoder WPM. The app works out the pauses for you.
  • Mode: Gap Multiplier — makes the pauses longer by a factor from 1× to 10×. Dots and dashes never change.
  • Wordsworth mode — when ticked, only the pauses between words get longer. In Gap Multiplier mode the normal word pause (7 dots long) is multiplied by 1 to 4, in steps of 0.5.

Farnsworth timing applies to every output that synthesises element timing: sidetone, vibration, MIDI, serial, Firebase RTDB, and audio key. WinKeyer output is not affected because the WinKeyer hardware generates its own timing. Keyer input (straight key or paddle) is not affected either: the keyer only sets the dit length, and you decide the gaps with your hands.

Example — Beginner Practice

Set Encoder WPM to 20, enable Farnsworth Timing with Effective WPM at 10. Characters arrive at 20 WPM speed — fast enough to sound natural — but the gaps between them are long enough that the overall throughput is only 10 WPM, giving you time to write each letter down.

8.6  Show Prosigns

Found in Settings → Other. Some prosigns (procedural signals, such as <AR> for “end of message”) have the same Morse pattern as a punctuation mark. When this is on, the full-screen conversation shows the prosign name instead of the punctuation mark. For example, + appears as <AR>.

PunctuationProsignMorse patternMeaning
+<AR>.-.-.End of message
&<AS>.-...Wait
=<BT>-...-Break / new paragraph
(<KN>-.--.Go ahead (one named station)

This changes only what you see. The app still sends and receives the punctuation mark. It applies to the full-screen conversation only; the main screen shows the punctuation. Prosigns with no matching punctuation (for example <SK> and <HH>) are always shown as prosigns.

8.7  Prosign Actions

Found in Settings → Other. When this is on, a decoded prosign can change the full-screen text, for example start a new line or clear the last word.

Did you know?
What operators meant by AR, SK, BT and KN

AR means “end of message”, SK “end of contact”, BT a pause or new paragraph, and KN “only the station I named should reply”. Each is sent as one run-together character, and AR and BT happen to sound exactly like the + and = signs.

Four prosigns are supported, each individually enabled and mapped to one of five actions:

Prosign Default Action Description
<AR> New Paragraph End of message — inserts two blank lines
<BK> New Line Break — inserts a line break
<BT> New Line New paragraph — inserts a line break
<HH> Clear Last Word Error — removes text back to the last space or newline boundary

Available actions:

  • New Line — inserts a single line break.
  • New Paragraph — inserts two line breaks (blank line separator).
  • Clear Last Word — removes text back to the last space or newline boundary (or the start of the buffer if there is none).
  • Clear Line — removes all text on the current line back to the previous newline (or the start of the buffer).
  • Clear Screen — clears the current fullscreen buffer entirely. Other buffers (main panel, the other fullscreen view) are not affected.

For the New Line and New Paragraph actions the prosign notation (e.g. <BT>, <AR>) is shown at the end of the current line before the line break is inserted, so you can see which prosign triggered the formatting. Destructive actions (Clear Last Word, Clear Line, Clear Screen) do not display the prosign.

Prosign actions only affect the fullscreen decoder and encoder conversation logs. The main screen panels always show the raw decoded text. The word-gap space that the decoder normally emits after a character is automatically suppressed when a prosign action fires, so new lines start without a leading space.

8.8  Emoji Replacements

When this is on, common Morse short forms, prosigns, Q-codes and 92 codes are shown as emoji in the full-screen conversation. This gives a quick picture of a greeting, a farewell or a signal report. The underlying text and the Morse are not changed. Emojis grow and shrink with the conversation font size.

Each mapping has a match pattern (case-insensitive), a replacement, and an optional meaning description. Matching is whole-word only: the pattern must appear at a word boundary on both sides (start of text, space, or newline). Prosign patterns such as <AR> also match their punctuation equivalents (e.g. +).

Match patterns can be single characters (e.g. +), prosigns (e.g. <AR>), or multi-character sequences (e.g. TNX, 73, QSL). The replacement text is not limited to a single emoji — it can be any mix of emojis and/or plain characters. For example, the default mapping for <KN> uses 🎤🔒 (two emojis), and you could map CQ to 📡 CQ (emoji followed by text).

The feature ships with a curated set of defaults (disabled by default). You can enable it, add your own mappings, reorder, or delete entries in Settings → Other → Emoji Replacements.

Example — Sample QSO with emojis & prosign actions

Copy and paste the text below into the encoder to see how prosign actions and emoji replacements work together in the fullscreen view:

CQ CQ CQ DE 5B4AON 5B4AON K
GA OM TNX FER CALL UR RST 599 599 QTH CYPRUS
WX IS FB HERE HI
QSL VIA LOTW GL 73 88 <SK>
Did you know?
73, 88 and CQ

In 1859 Western Union adopted number codes for common phrases. 73 meant “best regards” and 88 “love and kisses”, and radio amateurs still send both today. CQ, the call to all stations, was used on telegraph lines long before radio and is commonly said to stand for “seek you”. Q codes such as QTH (“my location”) came later for radio.
